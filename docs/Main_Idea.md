- `**01  ****The Core Thesis**` 

```
In the AI era, every specific skill is becoming commoditised. Anyone can write
code, generate designs, draft documents, or analyse data using AI tools. The
real differentiator — the skill that cannot be automated — is the **ability to
think through a problem.**
```

```
Two people open the same AI tool with the same problem. One solves it in ten
minutes. The other spins in circles for two hours and produces something broken.
The difference is not the tool — it is the mind operating the tool.
```

```
| **ProblemProof **captures, analyses, and certifies how a human thinks through
```

```
a problem — regardless of what tools they use. The process of solving reveals
the quality of the mind. That process is the credential. |
| --- |
```

```
ProblemProof does not care whether the participant used AI, documentation, Stack
Overflow, or pure reasoning. It does not test domain knowledge. It does not
measure output. It measures the one thing no AI can replace and no existing
system can verify: the quality of human reasoning under real conditions.
```

```
| *“A dual-stream capture system that records webcam video and screen activity
while a person solves a real problem, analyses the problem-solving process using
AI, gets the result validated by a trusted organisation, and stores a tamper-
proof credential on blockchain.”* |
```

```
## **Why Existing Verification Systems Are Broken**
```

- `| **System** | **What It Measures** | **Why It Is Broken** |` 

- `| --- | --- | --- |` 

- `| Coding tests (HackerRank, LeetCode) | Can you write correct code? | AI writes correct code. |` 

- `| Skill assessments (Coursera, Pluralsight) | Did you memorise the material? | AI memorises everything. |` 

- `| Portfolio review | What output did you produce? | AI produces any output on demand. |` 

- `| Interviews | Can you perform under social pressure? | Biased, inconsistent, unscalable. |` 

- `| Degrees & certifications | Did you complete an institution’s programme? | Proves access, not thinking ability. |` 

- `| Work samples | What did you produce? | Cannot verify the process behind the output. |` 

# `## **The Fundamental Gap**` 

```
There is no system in the world that verifies **how a person thinks through a
problem** — the one skill that remains irreplaceable in an AI-saturated world.
Every hiring process, credentialing body, and academic institution is still
measuring things that AI has made trivially easy to fake. The signal has
collapsed. ProblemProof rebuilds the signal.
```

```
**04  ****Layer 1 — Dual-Stream Capture**
```

```
Two synchronised streams are recorded simultaneously with a shared master
timestamp so every screen event maps to a corresponding cognitive state. This
synchronisation is the foundation of the system — it is what makes the analysis
meaningful rather than merely observational.
```

```
## **Stream A — Webcam (The Person, Not The Work)**
```

```
The webcam stream is never used to judge appearance. It captures physiological
and behavioural signals that reveal cognitive state in real time.
```

```
- **Liveness and identity verification** — Continuous, not just at login.
Prevents impersonation throughout the session.
```

```
- **Attention state** — Focused, reading, thinking, disengaged — detected via
gaze direction and blink patterns.
```

```
- **Cognitive load signals** — Gaze patterns, blink rate, and micro-expression
changes during difficulty spikes.
```

```
- **Frustration and confidence transitions** — When did the person get stuck?
When did something click?
```

```
- **Thinking posture** — Stillness during deep thought; physical restlessness
during confusion.
```

```
- **Authenticity correlation** — Micro-signals are cross-referenced with macro-
behaviour to detect staged performance.
```

```
| **Privacy commitment: **Webcam analysis runs on-device where possible. Only
extracted behavioural signals are sent to the server — never face video. Raw
```

```
recordings are encrypted, user-owned, and auto-deleted after a configurable
retention window (default: 30 days post-validation). |
| --- |
```

```
## **Stream B — Screen Recording + Structured Event Log**
```

```
**Screen video** — the full visual record of what happened on screen, used as
verifiable evidence by the validating organisation.
```

```
**Structured event log** — a lightweight parallel record of discrete events with
precise timestamps. This is the primary analysis input.
```

```
| **Event Type** | **What Is Captured** | **What Is Excluded** |
```

```
| --- | --- | --- |
```

```
| Application switches | App name, time entered, time exited | Window content |
```

```
| Copy/paste events | Frequency and timing | The text itself |
```

```
| Keystroke patterns | Timing rhythms (burst vs. deliberate) | Actual keystrokes
|
| Search queries | Query initiated (yes/no), tool used | Query text |
```

```
| Browser tabs | Opens, closes, domain category | Full URL or page content |
```

```
| AI tool sessions | Session opened, duration | Conversation content |
```

```
| File events | Open, save, switch | File content |
```

# `## **Synchronisation and Behavioural Fingerprinting**` 

```
Every webcam signal and every screen event shares a unified timestamp. This
enables statements like the following — which represent a behavioural
fingerprint that cannot be staged or faked:
```

```
| *“At 00:11:32, the screen showed a failed attempt. The webcam simultaneously
detected a frustration micro-expression. 38 seconds of stillness followed (deep
thinking state). At 00:12:10, systematic debugging behaviour began.”* |
| --- |
```

```
**05  ****Layer 2 — Workflow Analysis Engine**
```

```
The analysis engine is the core intelligence of the system. It takes the
synchronised dual-stream data and segments the session into problem-solving
phases using established cognitive science frameworks — primarily Polya’s
problem-solving model and design thinking phases — calibrated against a growing
dataset of real sessions.
```

# `## **Problem-Solving Phase Detection**` 

```
| **Phase** | **What the Engine Detects** |
```

```
| --- | --- |
```

```
| Understanding | Time spent reading, re-reads, note-taking behaviour,
requirement revisits before any action is taken. |
```

```
| Decomposition | Did the person break the problem into sub-problems? What was
their attack order? Was decomposition explicit or implicit? |
```

```
| Exploration | Resources consulted, tools opened, approaches tried, dead ends
pursued — breadth vs. depth of search. |
```

```
| Execution | Action sequences, iteration loops, tool fluency, progress rate —
doing vs. planning ratio. |
```

```
| Verification | Did the person test their solution? Check edge cases? Validate
assumptions before submitting? |
```

```
| Recovery | When something failed: how quickly did they recognise it,
backtrack, and revise? Speed and quality of course correction. |
```

# `## **The Process Graph**` 

```
From phase detection, the engine generates a **Process Graph** — a directed
graph representing the participant’s actual solving trajectory. No two Process
Graphs are identical. It is a cognitive fingerprint.
```

- `**Every branch point** — where they chose between approaches` 

- `**Every iteration loop** — where they refined a direction` 

- `**Every dead end** — where they tried something that failed` 

- `**Every recovery** — where they reversed course after failure` 

```
- **Every verification step** — where they checked their work
```

```
## **Key Metrics Extracted**
```

```
| **Metric** | **Definition** |
```

```
| --- | --- |
```

```
| Decomposition Quality | Did they break the problem down logically before
acting? Quality of sub-task identification. |
```

```
| Exploration Efficiency | How targeted was their search for information and
tools? Signal-to-noise in their exploration. |
| Verification Rigor | Did they check their work, or assume it was right? Number
and quality of verification steps taken. |
```

```
| Recovery Speed | How quickly did they recognise a wrong path and correct it?
Time-to-pivot after failure. |
```

```
| Persistence Pattern | Do they abandon too early, or push past productive
struggle? Calibrated against problem difficulty. |
```

```
| Decision Clarity | Are their branch-point decisions purposeful and consistent,
or apparently random? |
```

```
| Tool Fluency | How effectively do they use the tools available to them,
including AI tools? |
```

```
| Process Authenticity | Cross-correlation between webcam micro-signals and
macro-behaviour to detect staged performance. |
```

```
**06  ****Layer 3 — Process Profile**
```

```
The Process Profile is the output of the analysis engine. It is not a single
score. It is a structured, multi-dimensional report that gives every metric an
evidence trail. No score is asserted without a timestamped reference to the
session data that supports it. This evidentiary basis is what makes the
credential legally defensible.
```

# `## **Qualitative Narrative**` 

```
The engine generates a human-readable narrative — a plain-language summary of
what the session revealed. Examples:
```

```
| *“Demonstrated strong decomposition: broke the problem into 4 sub-tasks within
the first 3 minutes before any execution began.”* |
| --- |
```

```
| *“Verification rigor was low: submitted without testing edge cases on 3 of 4
attempts.”* |
| --- |
```

```
| *“Showed strong recovery: after a failed approach at minute 14, revised
hypothesis and converged on the correct path within 7 minutes.”* |
| --- |
```

```
| *“Exploration was broad but unfocused: visited 11 resources in 6 minutes
before settling on an approach — signal of low prior familiarity with the
domain.”* |
```

```
| --- |
```

```
## **Personal Baseline Calibration**
```

```
Before the real assessment, a short calibration task is run. People differ in
natural pace, blink rate, expressiveness, and working style. The system scores
against the person’s own baseline — removing bias against introverts,
neurodivergent individuals, and cultural differences in expression.
```

# `## **Credential Freshness and Decay Model**` 

```
A credential issued today is not permanent. Cognitive patterns, skills, and
habits evolve. ProblemProof implements a **credential freshness system**:
credentials carry an expiry indicator after 18 months. A lightweight
recertification session compares the new Process Graph against the stored
baseline to confirm consistency or document growth. This creates a longitudinal
record of how a person’s problem-solving evolves over time — a unique
professional asset.
```

```
**07  ****Layer 4 — Organisational Validation**
```

```
The organisation using the framework — employer, university, hackathon,
certification body — is the validator. This is intentional and non-negotiable.
```

# `## **Why Human Validation Is Non-Negotiable**` 

```
- A fully automated credential risks being wrong in consequential decisions
affecting careers and opportunities.
```

```
- The organisation knows the context of the problem better than any AI.
```

```
- Human validation makes the credential legally defensible in employment and
academic contexts.
```

```
- It prevents the system from being gamed through feedback loops on the AI
analysis.
```

```
The credential is the portable, permanent, verifiable record of the validated
```

```
**09  ****Problem Design Principles**
```

```
The quality of the problem given determines the quality of the signal captured.
Problems must be designed to make memorisation and answer-leaking impossible.
The **ProblemProof Problem Library** is a critical strategic asset — a managed
ecosystem, not a static bank of questions.
```

```
## **Properties of a Valid ProblemProof Problem**
```

```
- **Open-ended** — No single correct answer. Forces genuine process to emerge
rather than recall.
```

```
- **Ambiguous requirements** — Real-world problems never have perfect specs.
Handling ambiguity is itself a signal.
```

```
- **Multi-path** — Many valid approaches, none obviously superior. The choice of
path is meaningful signal.
```

```
- **Decisions under uncertainty** — Forces the participant to make judgment
calls without complete information.
```

```
- **Scalable depth** — Can be solved at a surface level or explored deeply.
Depth of engagement is signal.
```

```
- **Tool-agnostic** — Solvable with any tools, documentation, or AI. Using AI
well is not penalised.
```

```
- **Time-bounded ambiguity** — Cannot be fully solved in the session — how the
person manages this is revealing.
```

```
**10  ****Privacy Architecture**
```

```
Privacy is a core design value, not a compliance checkbox. The system is
architected to collect the minimum data necessary for each function, with user
ownership and control at every layer.
```

```
| **Principle** | **Implementation** |
```

```
| --- | --- |
```

```
| On-device processing | Webcam analysis runs locally where possible. Extracted
signals are sent to the server — never face video. |
```

```
| User-owned recordings | Raw recordings are encrypted with the user’s key. The
platform cannot access them without consent. |
```

```
| Behavioural patterns only | Event logs capture timing and frequency — not
keystrokes, not text, not file contents. |
```

```
| Auto-deletion | Raw recordings are deleted 30 days after validation by
default. Users can reduce this window. |
```

```
| Data portability | Participants can download their complete data package at
any time, in a standard format. |
```

```
| Right to erasure | Full session data can be deleted on request. The on-chain
credential hash remains (no personal data stored on-chain). |
| Regulatory compliance | Architecture satisfies GDPR (EU), PDPA
(Bangladesh/ASEAN), and PDPO (Hong Kong) by design. |
```

```
**11  ****Authenticity ****&**** Anti-Gaming Layer**
```

```
The most serious attack vector against ProblemProof is deliberate performance —
a person who knows to pause after failures, break problems into sub-tasks early,
and ‘verify’ visibly. This is addressed at the design level.
```

```
## **Why Deliberate Performance Is Detectable**
```

```
A person faking good process will have mismatched signals. Genuine deep thinking
produces characteristic webcam micro-signals — specific gaze patterns, blink
rhythm, micro-expression sequences — that are not consciously controllable. The
analysis engine cross-references these with macro-behaviour to generate a
**Process Authenticity score.**
```

```
| **Attack Vector** | **Detection Mechanism** |
```

```
| --- | --- |
```

```
| Staged pauses after failure | Webcam signals during the pause don’t match
genuine cognitive load patterns. |
```

```
| Artificial decomposition | Decomposition timing is unnaturally early and rigid
— doesn’t match natural exploration patterns. |
```

```
| Visible verification theatre | Verification behaviour is performed without the
characteristic micro-signals of genuine doubt. |
```

```
| Coached recovery patterns | Recovery speed is unusually consistent — genuine
recovery has high variance. |
```

```
| Memorised problem solutions | Process Graph lacks exploration branches
entirely — direct-path solutions with no dead ends are flagged. |
```

```
**12  ****Accessibility ****&**** Neurodivergence**
```

```
Personal baseline calibration is necessary but not sufficient for neurodivergent
fairness. The phase detection model itself must recognise that there are
multiple valid problem-solving styles — not one canonical linear model.
```

```
| **Archetype** | **Characteristics** | **Valid Signal** |
```

```
| --- | --- | --- |
```

- `| Linear-Sequential | Deliberate phase progression: understand → plan → execute → verify | Plan quality, execution precision |` 

```
| Exploratory-Iterative | Heavy exploration, multiple parallel threads, late
convergence | Exploration breadth, convergence quality |
```

```
| Intuitive-Validator | Rapid initial hypothesis, extended verification of the
hypothesis | Hypothesis quality, verification rigour |
```

```
| Non-Linear / ADHD-Adjacent | Frequent topic switches, ideas revisited multiple
times, parallel tracks | Completion rate, recovery from tangents |
| Minimalist | Very short exploration, direct execution, targeted verification |
Accuracy of initial framing, edge case awareness |
```

```
Participants may optionally disclose neurodivergent conditions to activate
adjusted scoring models. This is never required and never visible to the
validating organisation unless the participant explicitly chooses to share it.
```

```
## **Data Governance Charter**
```

```
- **Participant ownership**: Individuals own their data and can withdraw it at
any time.
```

```
- **Anonymisation before research use**: No session data is used in research
without full anonymisation and explicit opt-in.
```

```
- **No sale of individual data**: Individual records are never sold. Only
aggregate, anonymised insights are commercialised.
```

```
- **Transparency reports**: Annual reports disclosing how data is used, who has
accessed it, and what was derived from it.
```

```
- **Ethics board**: An independent ethics board reviews any new data use case
before implementation.
```

```
**17  ****Key Risks ****&**** Mitigations**
```

```
| **Risk** | **Severity** | **Mitigation** |
| --- | --- | --- |
```

```
| Credential adoption — orgs don’t know how to use process credentials | High |
Invest in employer education; provide benchmark data and comparison tools; start
with orgs that already believe interviews are broken. |
```

```
| Privacy backlash — webcam monitoring perceived as surveillance | High |
Reframe as coaching tool; on-device processing; user-owned data; strong privacy
marketing; opt-in for all sensitive signals. |
```

```
| Gaming at scale — coaching industry emerges | Medium | Process Authenticity
score; problem rotation; coaching-for-generic-process produces detectable
inconsistencies. |
```

```
| AI analysis accuracy — biased or incorrect profiles | High | Human validation
layer is non-negotiable; dispute resolution protocol; continuous model
improvement; third-party audits. |
```

```
| Regulatory risk — biometric data regulations tighten | Medium | On-device
processing first; no raw biometric storage; legal review in each target market;
GDPR-by-design. |
```

```
| Competition from incumbents building process analysis | Medium | Data moat;
problem library; blockchain credential portability; B2C flywheel creates demand
incumbents can’t easily replicate. |
```

```
| Org validator bias — validators favour similar candidates | Medium | Multi-
validator consensus in v2; bias detection in validation patterns; anonymised
candidate presentation option. |
```

```
**18  ****Open Research Questions**
```

```
These are the genuinely hard problems that require continued research and
empirical data to resolve. They are listed not as blockers but as the known
frontiers of the system.
```

```
### **Minimum viable session length**
```

```
What is the minimum session duration required to generate a statistically
reliable Process Profile? Preliminary hypothesis: 25–40 minutes, domain-
dependent.
```

```
### **Cross-cultural fairness**
```

```
Problem-solving style norms vary significantly across cultures. How do we ensure
the model is not implicitly calibrated to WEIRD (Western, Educated,
Industrialised, Rich, Democratic) populations?
```

```
### **Problem ungameability at scale**
```

```
Once problem types are known, people will practise for them. What is the half-
```

```
life of a problem’s signal quality, and how frequently must the library rotate?
```

```
### **Validator bias measurement**
```

```
How do we detect when a validator is systematically biased in their
confirmations? What data would reveal this pattern?
```

```
### **AI tool use as signal**
```

```
How a person uses AI tools is itself a problem-solving signal. How should the
system score effective AI use vs. over-reliance on AI suggestions?
```

```
### **Consent and power dynamics**
```

```
When a credential is required by a powerful organisation, is consent truly
voluntary? How do we protect candidates from coercive use of the system?
```

```
***“Can this person actually think through a hard problem?”***
```

```
ProblemProof captures the answer through dual-stream recording, analyses the
problem-solving process through a workflow analysis engine, gets the result
validated by a trusted human organisation, and issues a tamper-proof blockchain
credential that travels with the person globally. It does not test domain
knowledge. It does not measure output. It measures the process — the one thing
that remains irreplaceable in the AI era.
```
